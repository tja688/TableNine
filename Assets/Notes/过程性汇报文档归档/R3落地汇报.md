## 7. 风险、假设与后续

### 实现假设（待产品/主程确认）

- 荆棘甲伤害取设计文档 **2 点无视护甲**（`CombatConstants.ThornArmorDamage = 2`），与工厂 `TriggerDescription`「反弹1点」文案不一致，以实现文档为准。
- 凤凰羽毛恢复量为 **有效 MaxHp 的 50%（至少 1）**，非“回满”。
- 荆棘甲仅在玩家先手 `FirstHit` 组内并行（与 `战斗机制.md` / Plan §5 一致），怪物先攻后的玩家反击组不触发。

### 已知问题 / 技术债

- `OnBeforeCombat` / `OnAfterCombat` 现为事件桩，完整 SkillSystem/Relic 触发队列待 R5。
- 飞刀等帮助卡击杀收尾仍未走 `CommitPlayerActionCommand`（非本阶段范围）。

### 对下一阶段的建议

- R4 可将荆棘甲/刺皮迁入 EffectSystem `DamageAtom`，替换 `CombatSystem` 内硬编码分支。
- R5 实现 `SkillSystem` 时订阅 `CombatBeforeResolvedEvent` / `CombatAfterResolvedEvent`，避免再扩 Command。

- **日期**：2026-06-12
- **判定**：❌ 需整改后重新质检
- **核查范围**：汇报 §2 变更清单 + Plan §5 + ArchitectureDesign 相关章节
- **验证执行**：EditMode 10/10（`TableNineR3CombatPipelineEditModeTests`）；Console 0 error，1 warning（`MCP-FOR-UNITY: [WebSocket] Unexpected receive error: WebSocket is not initialised`）

### 问题摘要

R3 主干重构方向是对的，但当前实现还有 3 个不能按“小瑕疵”处理的问题。最严重的是 `CombatBeforeResolvedEvent` 的插点过晚，`BuildCombatContext` 已提前冻结有效属性与先攻结果，后续 R5 要接技能/遗物触发队列时将无法影响本次战斗的 stats 与 initiative。其次，并行伤害路径里的 `庇佑` 会在“原本不会造成伤害”的命中上被提前消耗，已偏离规则文档。最后，荆棘甲的触发语义从设计规定的“玩家先手同组”扩成了“玩家任意攻击组同组”，但专项测试没有覆盖这个分支，存在未确认假设落地。

### 符合项（可保留）

- `StartCombatCommand` 已从内联扣血改为编排入口，`ResolveCombatCommand` / `ApplyDamageGroupCommand` 负责实际结算，主干拆分方向正确。
- 并行伤害组对同目标采用护甲快照聚合，再统一落地，避免了串行先扣死导致后续同组伤害丢失的问题。
- `CommitPlayerActionCommand` 已接入空格点击、拾取帮助卡、战斗收尾，收尾口收敛方向正确。
- R3 专项 EditMode 测试实跑 10/10 通过，先攻、反击、凤凰羽毛、单次提交动作这些主路径已有回归保护。
