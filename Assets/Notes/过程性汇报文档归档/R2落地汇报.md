## 7. 风险、假设与后续

### 实现假设（待产品/主程确认）

- 怪物节点开护甲与玩家相同，按有效 Defense 填充。
- 房间宝箱/商店完成后直接 `ProceedToNextNode`，不再二次弹出帮助奖励。
- `OpenShopCommand` + `CloseShopCommand` 独立入口仍保留旧「关店→帮助奖励」路径（非节点房间流）。

### 问题摘要

R2 的核心规则值行为已经基本对齐：护甲填充、伤害公式、帮助卡默认永久移除和清场后先帮助奖励再房间，这些专项测试都通过了。真正没收口的是“状态变更事件契约”这一层：规则已经改了，但对 UI / Anim / Debug 承诺的 `ArmorChangedEvent` 与 `StatsDirtyEvent` 还没有在所有护甲路径上补齐。这个问题会直接影响后续 R3-R8 的订阅方稳定性，因此本阶段不建议归档。

### 符合项（可保留）

- `FillArmorFromDefenseAtNodeStart` 已在开局发牌结束后执行，玩家与场上怪物都能按有效防御补护甲。
- `CombatSystem.CalculateDamage` / `BuildCombatDamage` 已改为基于 `DamageReduction`，不再读取 defender `Defense` 扣伤。
- `CheckClearConditionCommand -> GenerateHelpRewardCommand -> EnterRoomChoosingCommand` 的流程顺序已落到命令链。
- `ConsumeHelpCardCommand` 已改为内部读取 `RestoreAfterNode`，调用方不再传 `permanentlyRemove`。
