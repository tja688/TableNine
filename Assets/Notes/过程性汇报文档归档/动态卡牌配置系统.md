# 动态卡牌配置系统（运行时 Prefab 绑定）

> **已归档**：请改读 [`Assets/Notes/卡牌烘焙与显示系统.md`](../卡牌烘焙与显示系统.md)

> 面向后续 AI / 开发者的操作笔记。  
> 与「烘焙成贴图再旋转」的临时方案（见 `Assets/Notes/烘焙卡牌管线.md`）并存；**正式体验与 SO 联调走本文档的 Prefab 绑定路径**。

---

## 1. 系统目标

用 **SO 配置 + 场景 Prefab 子物体** 动态拼出卡面，无需为每张卡单独做美术 Prefab：

- 卡面/卡背：按 **牌组 `DeckId`** 取 `DefaultFaceImage` / `DefaultBackImage`
- 主图标：卡牌 `Image`（导师卡可回落到关联技能图标）
- 数值与技能角标：按 `CardType` 显隐
- 描述：`DescriptionText` 悬停组合文案，**多行显示**

当前主要用于 **场景内预览 Demo**；架构上 `CardExampleFaceBinder` 可被正式 `CardView` / 棋盘表现层复用。

## 3. Prefab 节点约定（`CardExample`）

绑定器按 **子物体名称** 查找（递归），改名会破坏绑定：

```
CardExample (根，需 BoxCollider2D 供悬停)
├── CardFront          → SpriteRenderer，牌组卡面（框/底图）
│   ├── CardMainIcon   → SpriteRenderer，卡牌主图标
│   ├── CardAttackIcon / CardDefenseIcon / CardLifeIcon
│   └── EntryIcons     → 技能角标容器（Icon_0 / Icon_1 / …）
├── CardTextCanvas     → CardName / CardAttack / CardDefense / CardLife (TMP)
└── CardBack           → SpriteRenderer，牌组卡背
```

**不要**把 `GetEffectiveCardFaceImage` 设到 `CardMainIcon`；卡面与主图标是两层。

## 4. SO 数据模型

### 4.1 牌组 `CardDeckDefinition`（`TableNineCardConfig.asset` → `CardDecks`）

| 字段 | 用途 |
|------|------|
| `DeckId` | 如 `deck_common`、`deck_tutor`、`deck_weak_elite` |
| `DefaultFaceImage` | 该牌组默认卡面 Sprite |
| `DefaultBackImage` | 该牌组默认卡背 Sprite |

运行时解析（`ConfigModel`）：

- 卡面：`card.FaceImageOverride ?? deck.DefaultFaceImage`
- 卡背：`card.BackImageOverride ?? deck.DefaultBackImage`
- 主图标：`card.Image`

### 4.2 卡牌 `CardDefinition`（`TableNineCardConfig.asset` → `Cards`）

| `CardType` | 预览池 | 卡面布局 |
|------------|--------|----------|
| `Monster` | ✅ | 名 + 主图标 + 血攻甲 + 技能角标（`EntryIcons`） |
| `Help` | ✅ | 名 + 主图标，**隐藏**血攻甲与技能角标 |
| `Tutor` | ✅ | 同帮助卡；主图标优先 `Image`，否则 `SkillIds[0]` 的技能图 |
| `Player` | ❌ | 用 `PlayerCard.prefab` + `CharacterDefinition`，非本系统 |
| `Room` | ❌ | `RoomDefinition`，非 CardDefinition |

### 4.3 导师卡（`CardType.Tutor`）

- **牌组**：`deck_tutor`（`GameConfigIds.DeckTutorId`）
- **CardId 规则**：`tutor_{skillId}`，见 `GameConfigIds.GetTutorCardId(skillId)`
- **生成**：`DefaultGameConfigPlaytestContent.AddPlaytestTutorCards()`，数据源为 `GameConfigIds.TutorSkillPoolIds`
- **字段约定**：
  - `DisplayName`：技能名
  - `SkillIds`：单元素，指向导师技能
  - `Description`：留空；悬停只显示 **技能 Description**
  - `Image`：可空；Sync 时会从关联技能复制图标

在编辑器中为导师牌组单独指定 `DefaultFaceImage` / `DefaultBackImage` 即可换导师专属卡框。

## 5. 绑定逻辑速查（`CardExampleFaceBinder.Apply`）

```
1. CardName  ← DisplayName
2. 血攻甲 TMP + 图标 ← BaseHp / BaseAttack / BaseArmor（仅 Monster 显示）
3. CardFront / CardBack ← GetEffectiveCardFaceImage / GetEffectiveCardBackImage
4. CardMainIcon ← Image；Tutor 且无 Image 时用 SkillIds[0] 的技能图
5. EntryIcons ← Monster 且有 SkillIds 时，按顺序贴技能 Image
```

---

## 6. 描述组合（`CardPreviewDescriptionComposer`）

悬停时写入场景 `DescriptionText`（`DescriptionPanel` 下 TMP）。

| 类型 | 行内容 |
|------|--------|
| Monster | 第 1 行：`card.Description`；后续行：每个技能的 `Description` |
| Help | 第 1 行：`card.Description`；后续行：主动/被动效果摘要（EffectGraph + Help 被动绑定） |
| Tutor | **仅**关联技能的 `Description`（一行或多技能多行） |

格式化：`DescriptionPanelTextRules.FormatDisplayLines(parts)` — 段与段之间 **`\n` 换行**，每行仍受 `MaxLength = 25` 截断。  
SO 入库文案仍用 `SanitizeForStorage`（去掉换行）；**仅预览悬停**允许多行。

## 7. 场景 Demo 接线

### 7.1 组件挂载

- **挂载位置**：`NineGrid Main CardSlots/CardSlot1`（父物体，**不要**挂在 `CardExample` 上）
- **原因**：`GameplayWorldPresenter` 会把场景里的 `CardExample` 当模板 `SetActive(false)`；父物体上的 `RandomCardPreviewDemo`（`DefaultExecutionOrder(100)`）会在其后重新 `SetActive(true)`
- **子引用**：自动查找子节点 `CardExample` 为 `mCardRoot`

### 7.2 操作

| 输入 | 行为 |
|------|------|
| **空格** | 从 Monster + Help + Tutor 池随机切一张（排除 Player / Room） |
| **鼠标悬停卡面** | `DescriptionText` 显示组合描述（多行） |
| **移开** | 恢复默认提示文案 |

### 7.3 随机池构建

`RandomCardPreviewDemo.BuildRandomPool()` → `GetCardsByType(Monster|Help|Tutor)`，过滤 `Player` / `Room`。

## 8. 配置工作流（给 AI 的清单）

### 8.1 新增普通帮助卡 / 怪物卡

1. 在 `TableNineCardConfig`（或代码默认 `DefaultGameConfigFactory`）增加 `CardDefinition`
2. 设置 `DeckId`、`Image`、`Description`、数值（怪物）、`SkillIds`（可选）
3. **不要**只跑 Sync 而不补图：Sync 现已 **保留**已有 Sprite，但新条目 `Image` 仍可能为空
4. 缺图标时：`TableNine → Game Config → Fill Main Icons From Pixel Store`

### 8.2 新增导师技能卡

1. 在 `TableNineSkillConfig` 增加 `SkillDefinition`（含 `Image`、`Description`）
2. 将 `skillId` 加入 `GameConfigIds.TutorSkillPoolIds`
3. `TableNine → Game Config → Sync From Code Defaults` → 自动生成 `tutor_{skillId}` 卡牌条目
4. Sync 会自动：`deck_tutor` 归属 + 从技能复制 `Image`（若卡图为空）
5. 在 `CardDecks` 里配置 `deck_tutor` 的专属卡面/卡背

### 8.3 更换某牌组卡框

只改 `CardDecks` 中对应 `DeckId` 的 `DefaultFaceImage` / `DefaultBackImage`；无需改每张卡。

### 8.4 单卡覆写卡面/卡背

在 `CardDefinition` 设 `FaceImageOverride` / `BackImageOverride`。

## 9. 与正式表现层的关系

| 模块 | 状态 |
|------|------|
| `CardView` / `CardViewPresenter` | 灰盒文字 + 单 Sprite，尚未接 `CardExampleFaceBinder` |
| `BakedCardFaceComposer` | 编辑器离屏烘焙贴图，Play 模式 `LoadTemplate` 为 null，**仅 Editor 可用** |
| `RandomCardPreviewDemo` | **当前 SO → 卡面预览的标准入口** |

**若要把正式棋盘卡面切到动态 Prefab：**

1. 棋盘上的卡 Visual 实例化 `CardExample`（或子集）
2. 状态变更时调用 `CardExampleFaceBinder.Apply(root, definition, configModel)`
3. 悬停描述复用 `CardPreviewDescriptionComposer.Compose`
4. 玩家卡继续用 `PlayerCard.prefab`，不走 `CardExample`

## 10. 已知坑点（必读）

1. **Sync From Code Defaults 曾清空全部 Sprite**  
   已修复：`TableNineGameConfigSync` 同步前会 `Preserve*Visuals` 保留已有引用。新 ID 仍可能没有图，需 Fill Icons 或手配。

2. **`GameplayWorldPresenter` 隐藏 `CardExample`**  
   Demo 组件必须挂在 **父节点** 并在 `Start` 里重新激活子 `CardExample`。

3. **描述字数**  
   `DescriptionPanel` 单行上限 25 字（含标点）；多行时每行独立截断。长文案要在 SO 里控制长度。

4. **烘焙管线 vs 本系统**  
   `BakedCardFaceDemoRoot` 与 `RandomCardPreviewDemo` 不要混用同一 `CardExample` 实例；烘焙是贴图旋转实验，本系统是 SO 直驱 Prefab。

5. **导师卡运行时选技能**  
   `RewardSystem.GenerateTutorSkillCandidates()` 仍用 **技能 ID 池**，尚未改为读 `CardType.Tutor` 的 CardDefinition；UI 接导师三选一时需自行对齐。
