## 2. P0 硬问题（续接前必须补齐或明确降级）

> **定义**：不解决会导致后续效果/UI/对象接入时返工、或 M5 验收名不副实。

### P0-1. EffectSystem 为空壳，帮助卡逻辑硬编码在 Command

- **设计**：`EffectSystem.ResolveEffectGraph` + `IEffectAtom` 流水线（ArchitectureDesign §6.7、Plan 阶段 6）
- **现状**：`EffectSystem.OnInit()` 为空；`UseHelpCardCommand` 用 `switch(cardId)` 硬编码（`RuntimeCommands.cs` L578–642）
- **缺口**：`PlaytestHelpCardIds` 共 **20** 张，已实现约 **7** 张（药水、飞刀、属性提升、宝箱系、金币卡、庇佑）；其余走 `MsgNotImplemented`
- **风险**：每加一张帮助卡都要改 Command switch，无法接 Odin 效果图，与架构「规则先于表现、效果只认接口」冲突
- **建议**：先落地 EffectSystem MVP（6 个基础 Atom）→ 将已实现 7 张迁移到效果图或 Atom 注册表 → 再批量接剩余 13 张

### P0-2. SkillSystem 与 EffectTriggerQueue 完全缺失

- **设计**：统一触发队列 + 防递归（ArchitectureDesign §10.9、Plan 阶段 9）
- **现状**：`TableNine.cs` 未注册 `ISkillSystem`；全库无 `EffectTriggerQueue` 符号
- **缺口**：怪物技能仅部分在 `StatSystem` 做格位/先攻修正（四幼崽 + `GrantsFirstStrike`）；移动触发、光环、召唤、决斗锁、复仇等均未接线
- **风险**：后续做 Anim/特效时会在 Command 里继续堆 `if skillId` 分支，触发递归无法防
- **建议**：最小可行 `SkillSystem`（收集触发项 → 排序 → 调 EffectSystem）+ 单 Command 触发上限 + Debug 链日志

### P0-3. 遗物/玩家技能「配置有、触发无」

| 内容 | 配置 | 运行时 |
|------|------|--------|
| 凤凰羽毛致命伤免死 | `RelicPhoenixFeatherId` | ❌ 战斗管线无 `ApplyDeathPrevent` |
| 荆棘甲反伤 | `RelicThornArmorId` | ❌ |
| 活着的肉 | 配置存在 | ❌ |
| 木盾/木剑/木甲套装 | stat 字段存在 | ❌ 无三件套 `StatSystem` 判定 |
| 轻车熟路 | 小鬼初始技能 | ❌ 无 `OnNodeClear` 插白色三选一 |
| 导师技能（刺皮/硬皮等） | `ChooseTutorSkillCommand` 仅 `AddSkill` | ❌ 无效果逻辑 |
| 宝箱品质概率（白/蓝/金） | 设计有分歧项 | ❌ `GenerateChestRewardCandidates` 统一池 |

- **证据**：`RelicSystem`（`RuntimeSystems.cs` L876+）管添加/候选/属性加总；`System/` 目录无 Phoenix/Thorn 战斗引用
- **风险**：M3/M5 测试只验证「能拿到遗物」，不验证「遗物改变战斗」——玩家会遇到「拿了没用」的阻断体验

### P0-4. 战斗管线过度简化

- **设计**：Validate → BeforeCombat → 伤害结构 `DamageContext` → 荆棘/免死 → AfterCombat → KillSettlement（§6.5、§10.8）
- **现状**：`StartCombatCommand` 双向 `ApplyDamage` + 旋转 + 补牌（`RuntimeCommands.cs` L365–438）；无 `CombatStartedEvent`、无 `CommitPlayerActionCommand`
- **连带缺口**：
  - 无「怪物存活反击」集成测试（仅有 API 级「死亡不反击」）
  - 庇佑仅在 `ApplyDamageCommand` 处理 `PendingHelpCardAction`，非通用伤害免疫层
  - `GameOverCommand` / `VictoryCommand` 内联，非独立 Command
- **建议**：至少抽出 `CommitPlayerActionCommand`、补全反击集成测试，再接遗物/技能修改伤害

### P0-5. 存档无跨会话持久化（M5 声称偏差）

- **设计**：`EasySaveUtility` + ES3（§15.1）
- **现状**：`TableNine.cs` L23 注册 `MemorySaveUtility`（进程内字典）
- **影响**：`SaveRunCommand` / `LoadRunCommand` 在同进程测试往返 ✅（`TableNineM5EditModeTests.SaveLoad_Roundtrip_*`），**退出游戏后存档丢失**
- **建议**：接入 `EasySaveUtility` 或文档明确标注「M5 存档仅内存替身，持久化推迟 M6」

### P0-6. Command 重放无法复现棋盘状态（M5 声称偏差）

- **设计**：seed + command list 复现吞卡/并发 Bug（§17.3、Plan 阶段 14）
- **现状**：`CommandReplayFactory` 仅支持约 7 种命令；`ReplayRunCommand` 测试只断言 seed/层/节点（`TableNineM5EditModeTests` L118–134）
- **缺口**：无日志落盘；payload 为管道字符串非架构示例 JSON
- **建议**：扩展 Replay 工厂覆盖 M1–M3 主路径 Command；增加「重放后棋盘 hash 一致」断言

### P0-7. M5「全 playtest」与 Plan 验收标准差距

Plan M5 验收：

> 可完整通关或失败；**存档/读档/重放/Debug 面板可用**；**3 层 27 节点，全部核心卡/怪/技能/遗物上线**

| 子项 | 状态 |
|------|------|
| 27 节点配置可进入 | ✅ |
| 全部核心卡效果上线 | ❌（约 35% 帮助卡运行时） |
| 全部怪物技能上线 | ❌（配置全、触发极少数） |
| 全部遗物上线 | ❌（CRUD 有、战斗触发无） |
| 跨会话存档 | ❌ |
| 重放等效状态 | ❌ |
| Debug 面板达标 | ⚠️（见 §4.5） |

**质检裁定：M5 不可标记为完成；应回退为「M5-配置就绪 / M5-运行时进行中」。**
