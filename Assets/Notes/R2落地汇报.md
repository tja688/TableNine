## 4. 架构符合性

- **Command 改状态**：护甲/伤害/消耗/流程均经 Command，符合 QFramework 四层约定。
- **Defense 与 DamageReduction 分离**：Defense 用于节点护甲填充与显示；战斗减伤只用 DamageReduction。
- **RestoreAfterNode 为帮助卡语义唯一入口**：`ConsumeHelpCardCommand` 不再接收 `permanentlyRemove` 参数。

## 7. 风险、假设与后续

### 实现假设（待产品/主程确认）

- 怪物节点开护甲与玩家相同，按有效 Defense 填充。
- 房间宝箱/商店完成后直接 `ProceedToNextNode`，不再二次弹出帮助奖励。
- `OpenShopCommand` + `CloseShopCommand` 独立入口仍保留旧「关店→帮助奖励」路径（非节点房间流）。

### 已知问题 / 技术债

- L2/L3 怪物配置缺口导致 M4/M5 部分用例仍失败 — 与 R0 一致，建议配置补全或 R9 前处理。
- R3 需将 `StartCombatCommand` 拆为 `CombatContext` + 并行伤害组。

### 对下一阶段的建议

- R3 改造战斗管线时复用 `BuildCombatDamage` 与 `ApplyDamageCommand(DamageContext)`，勿回退 int 伤害。
- 荆棘甲/刺皮等反伤在 R3 作为并行伤害组接入。
